SlabMaster REST API & SAP S/4HANA Integration

A modern, high-throughput RESTful JSON API designed for SAP enterprise resource planning, Project Systems (WBS), and field fabrication synchronization.

Why This API Supersedes Moraware

  • First-Class External ID Routing: Use SAP WBS Elements, Purchase Orders, and Lot codes directly in REST paths and upsert payloads without internal UUID translation tables.
  • Full CRUD with Idempotent Upserts: Eliminates duplicate creation errors caused by network re-transmissions.
  • Two-Way Change Data Capture (CDC): SAP polls clean delta feeds to capture shop floor progress, digital templating signoffs, and completed installs.
  • Audit-Compliant Soft Cancellation: Protects SAP cost accounting by flagging records as cancelled rather than breaking foreign keys.
  • Automated Dead-Letter Queue: Outbound pushes to SAP use progressive backoff (1m ? 5m ? 15m ? 1h) with manual retry controls in the Admin Portal.

?? 2. Authentication & Security

Every REST request requires a tenant-scoped API key passed via standard HTTP headers:

# Recommended Header Format:
X-API-Key: sm_live_9f83a1b4c7e28910fedcba45

# Or Standard Bearer Authorization:
Authorization: Bearer sm_live_9f83a1b4c7e28910fedcba45
Token Generation: Tenant administrators generate integration keys in the SlabMaster Admin Portal under Settings ? API & ERP Integration. Tokens are SHA-256 hashed prior to storage and can be scoped with read, write, sync, and delete permissions.

?? 5. SAP ABAP Integration Code Sample

SAP developers can use the standard cl_http_client class to push orders from SAP S/4HANA or ECC to SlabMaster:

REPORT z_slabmaster_job_upsert.

DATA: lo_http_client TYPE REF TO if_http_client,
      lv_url         TYPE string VALUE 'https://dev.slabmasterapp.com/api/v1/jobs/upsert',
      lv_api_key     TYPE string VALUE 'sm_live_9f83a1b4c7e28910fedcba45',
      lv_json        TYPE string,
      lv_response    TYPE string,
      lv_subrc       TYPE sy-subrc.

" Build JSON payload from SAP Sales Order / WBS
lv_json = '{"external_id":"SAP-ORD-90210",' &&
          '"account_external_id":"SAP-BLD-01",' &&
          '"community_external_id":"COMM-HIGHLAND",' &&
          '"lot_external_id":"LOT-HIGHLAND-14",' &&
          '"job_name":"Kitchen Perimeter & Island",' &&
          '"target_install_date":"2026-09-22T00:00:00Z"}'.

" Create HTTP Client by URL
cl_http_client=>create_by_url(
  EXPORTING url    = lv_url
  IMPORTING client = lo_http_client ).

" Set Headers
lo_http_client->request->set_method( if_http_request=>co_request_method_post ).
lo_http_client->request->set_header_field( name = 'X-API-Key' value = lv_api_key ).
lo_http_client->request->set_header_field( name = 'Content-Type' value = 'application/json' ).
lo_http_client->request->set_cdata( lv_json ).

" Send and Receive
lo_http_client->send( ).
lo_http_client->receive(
  EXCEPTIONS
    http_communication_failure = 1
    http_invalid_state         = 2
    http_processing_failed     = 3
    OTHERS                     = 4 ).

IF sy-subrc = 0.
  lv_response = lo_http_client->response->get_cdata( ).
  WRITE: / 'SlabMaster Synchronized Successfully:', lv_response.
ELSE.
  WRITE: / 'Error Calling SlabMaster API:', sy-subrc.
ENDIF.

lo_http_client->close( ).

??? 7. Outbound Resilience & Dead-Letter Queue

When SlabMaster pushes milestones back to SAP and encounters network interruptions or SAP maintenance downtime, events enter the Outbound ERP Retry Queue with automated progressive backoff:

Attempt # Backoff Delay Target Failure Type
Attempt 1 Immediate (0s) Transient socket/TLS negotiation resets
Attempt 2 1 Minute Brief microservice restarts
Attempt 3 5 Minutes Rate limit (HTTP 429) backoff
Attempt 4 15 Minutes Load balancer failovers
Attempt 5 1 Hour Scheduled maintenance windows
Exhausted Stuck / Dead-Letter (FAILED) Requires admin review & manual retry trigger

Manual Recovery Endpoints

# Retry a specific stuck item:
POST /api/v1/sync/queue/queue-tx-9941/retry

# Batch retry all failed items in the dead-letter queue:
POST /api/v1/sync/queue/retry-all
